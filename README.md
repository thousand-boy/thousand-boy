## ポートフォリオ

### [勤務表作成支援ツール](https://github.com/thousand-boy/kinmu-automation)

**Excelの職員情報と勤務希望から、勤務表の下書きを作るPythonツールです。現在は条件と動作を検証する試作品です。**

希望休を反映すると、別の日の人数や他の職員の連勤にも影響します。この調整を支援するため、業務ルールを「必ず守る条件」「できるだけ満たす条件」「人が判断する内容」に分けて扱っています。

#### 実装している機能

- **勤務割当**：OR-Toolsで複数の条件を同時に扱い、勤務と休みを配置します。理由付きの固定予定、必要休日数、日曜の各病棟2名を必須とし、その他の人数・役割の目安はできるだけ満たす条件として扱います。
- **Excel入出力**：openpyxlで職員情報と勤務希望を読み込み、結果を出力します。職員追加時の行作成や、在籍対象外の職員を最適化・集計から除く処理があります。
- **保存後の検証**：一時保存したExcelを再読み込みし、数式・固定予定・休日数などを確認してから正式な出力へ置き換えます。
- **テストとコード管理**：pytestによる99件のテスト（統合2件を含む、2026年9月28日時点）があり、職員変更、入力不備、保存失敗などを検証する構成です。Gitで履歴を管理し、GitHub Actionsでテストを自動実行する設定もあります。

#### 開発で重視していること

自動で配置するだけでなく、**担当者が確認・調整すべき箇所を分かるようにすること**を重視しています。出力をそのまま確定する想定ではなく、現場での継続運用や時間削減効果は未検証です。

AIは疑問点の整理、技術の選定、実装・修正案の検討に活用しています。提案された処理は勤務条件と照合し、サンプル実行や出力Excelの確認を通じて確かめています。コードの動作を自分の言葉で説明できるよう、資料とコードを読み直して学習を続けています。

対応する条件や制限、処理の流れ、テストの詳細は[リポジトリのREADME](https://github.com/thousand-boy/kinmu-automation#readme)にまとめています。公開サンプルは匿名化したデータを使用しています。

#### 今後の開発計画

1. **Pythonの中核処理を検証・改善する**：勤務条件や職員変更に対する動作を確かめる。
2. **必要に応じてバックエンド機能を拡張する**：API化やデータ管理を追加する。
3. **ブラウザから操作できる画面を作る**：HTML・CSS・JavaScriptで、条件入力・実行・結果確認を行う画面へ発展させる。

API・データベース・Web画面は未実装です。まずは処理の検証を優先し、利用者の操作性も段階的に改善する計画です。
